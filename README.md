# Profile Editor

Инструменты для оформления профиля Steam. Всё считается прямо в браузере, файлы никуда не загружаются, аккаунт не нужен.

## Что умеет

- нарезка картинок, гифок и видео под витрины: иллюстрации, избранная иллюстрация, скриншоты, мастерская
- комплект: один арт режется сразу на все витрины профиля, они стоят друг под другом и картинка идёт через них без швов;
  из того же арта вырезается аватар 184×184; между витринами комплекта можно поставить свою,
  например информационную, — всё ниже сдвинется на её высоту; фон профиля, рамка и анимированный аватар
  из магазина очков выбираются прямо в каталоге и запоминаются вместе с комплектом
- гифки до 5 МБ, у всех частей одинаковые кадры, чтобы анимация не разъезжалась; в кадр пишется только то,
  что поменялось, поэтому в лимит влезает больше кадров и цветов
- конструктор: фон, картинки и надписи слоями, вырезка фона у картинки; анимация готовыми движениями
  или по ключам — где слой в какой момент цикла, а между ключами он движется плавно
- конструктор умеет собирать сразу на весь профиль: слои лежат на общем холсте, а на выходе части всех витрин
- оформление картинок: обводка, свечение, тень, растворение края и режимы наложения
- проекты конструктора сохраняются в браузере сами, их можно скачать файлом и открыть на другом компьютере
- превью профиля, в том числе своего по ссылке или SteamID
- каталог фонов, рамок и аватаров из магазина очков, подбор фона по цвету
- редактор текстового блока: BBCode, ASCII-арт, центровка
- расширение для Chrome и Яндекс Браузера или юзерскрипт, которые сами подставляют коды на странице загрузки Steam;
  витрину для частей из нашего архива они понимают по имени файла

## Запуск

Нужен Node 24.

```
npm install
npm run dev
```

Никаких ключей Steam не нужно: профиль ищется по ссылке, нику из ссылки или SteamID64 через открытые данные Steam.

`npm audit` ругается на `sharp` и `adm-zip`. Оба приезжают с `@huggingface/transformers` ради его
серверных бэкендов, в браузерную сборку они не попадают. Поднять их версии через `overrides` не
выходит: у `onnxruntime-node` от этого падает постинсталл и перестаёт проходить `npm ci`. Ждём,
когда их вынесут в необязательные зависимости.

Остальные команды: `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`.

Тесты идут двумя наборами: `packages` считаются в node, код сайта — в jsdom с поддельной IndexedDB.
Только один из них: `npx vitest run --project core` или `--project web`.

Прогон в настоящем браузере — `npm run build && npm run e2e`: собирает витрину, кодирует гифки
и переносит их в превью профиля, складывая скриншоты каждого шага. Ключи перечислены в шапке
`scripts/e2e/showcase.mjs`.

`npm run e2e:kit` проверяет комплект: режет один арт на все витрины, разбирает архив и смотрит,
как части и аватар встали в превью профиля. Цвет каждой точки тестового арта хранит её координаты,
поэтому прогон сверяет с точностью до пикселя, что каждая часть в превью стоит там, откуда её
вырезали. Ключ `--gif` собирает комплект из гифок и проверяет, что во всех частях поровну кадров,
`--builder` прогоняет тот же комплект, собранный слоями в конструкторе.

`npm run e2e:styles` проверяет оформление по пикселям готового файла: обводку, свечение,
растворение края и то, что с оформлением гифка собирается так же быстро.

`npm run e2e:helper` ставит собранный помощник загрузки на макет страницы Steam и проверяет, что по
имени файла он выбирает витрину и выставляет её поля, а витрину, нажатую руками, не перебивает.

## Структура

- `apps/web` — сайт (React, Vite, Tailwind)
- `packages/core` — размеры витрин, работа с гифками, файлы проектов, запросы к Steam
- `packages/userscript` — помощник для страницы загрузки Steam, из него собираются юзерскрипт и расширение
- `scripts/catalog` — выгрузка каталога магазина очков, запускается в GitHub Actions раз в сутки
- `scripts/e2e` — прогоны в браузере: конструктор (`showcase.mjs`), комплект на весь профиль (`kit.mjs`),
  оформление картинок (`styles.mjs`) и помощник загрузки (`helper.mjs`)
- `scripts/measure-profile.mjs` — замер раскладки витрин на живом профиле Steam
- `scripts/og-image.mjs` — рисует картинки для превью ссылок, `apps/web/public/og-ru.jpg` и `og-en.jpg`
- `api` — серверная функция для Vercel, ходит в Steam Web API

## Раскладка профиля

Где стоят витрины, нарезка и превью берут из `packages/core/src/layout.ts` и `kit.ts`. Числа сняты
с живых профилей: `node scripts/measure-profile.mjs https://steamcommunity.com/id/<ник>` открывает
профиль в браузере шириной 1920 и меряет, где внутри блоков стоят картинки и сколько места под ними.
Если Steam поменяет вёрстку, перемерить на паре профилей с витринами и поправить числа там же —
в тестах `kit.test.ts` лежат высоты блоков, снятые с живых профилей.

## Деплой

Сайт живёт на Vercel, настройки лежат в `vercel.json`. Переменные окружения не нужны.

Мессенджеры и часть поисковиков не запускают скрипты, поэтому сборка кладёт на каждый адрес свой
html (`ru/cutter.html` и так далее) с заголовком, описанием и картинкой для превью ссылки, плюс
`sitemap.xml` и `robots.txt`. Для ссылок в тегах нужен адрес сайта: на Vercel сборка берёт его из
`VERCEL_PROJECT_PRODUCTION_URL`, на другом хостинге его задают через `SITE_URL`. Без адреса теги
собираются без абсолютных ссылок, а карты сайта нет.

Там же заголовки безопасности. В CSP списки хостов намеренно широкие: нарезчик открывает
картинку по любой ссылке, а вырезка фона тянет onnxruntime с jsdelivr и модели с Hugging Face.
Политика проверена прогоном по самому тяжёлому пути, включая вырезку фона и сборку гифок.
